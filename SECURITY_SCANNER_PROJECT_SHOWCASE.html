Codebase Deep Dive: Architectural Modules

1. Finding Fingerprint & Deduplication Engine app/core/fingerprint.py & app/core/scoring.py
Implemented

Each vulnerability is assigned a deterministic fingerprint calculated by normalizing the scheme, stripping default ports (80/443), ordering query parameters alphabetically, and generating a SHA-256 hash. When a subsequent scan runs on the same target, findings with matching fingerprints are recognized as duplicate instances of the same underlying defect: 

def compute_finding_fingerprint(category: str, title: str, affected_url: str, discriminator: str = "") -> str:
    norm_cat = category.strip().lower()
    norm_title = title.strip().lower()
    norm_url = normalize_url_for_fingerprint(affected_url)
    norm_disc = discriminator.strip().lower()

    payload = f"{norm_cat}|{norm_title}|{norm_url}|{norm_disc}"
    return hashlib.sha256(payload.encode("utf-8")).hexdigest()

Security Scoring: The overall score starts at 100.0. Penalties are deducted for unique open findings (Critical: 25, High: 15, Medium: 8, Low: 3), scaled by confidence. Duplicate findings are discounted from double deductions.

2. API Security Scanner app/scanners/api_security.py
Implemented

Performs non-destructive checks against API endpoints and headers:

  • Missing Security Headers: Audits CSP, HSTS, X-Content-Type-Options (nosniff), X-Frame-Options (DENY/SAMEORIGIN), and Referrer-Policy.
  • Weak CSP Directives: Detects dangerous 'unsafe-inline' and 'unsafe-eval' script directives.
  • CORS Misconfiguration: Probes with an unauthorized origin header to detect wildcard origin reflection combined with Access-Control-Allow-Credentials: true.
  • Dangerous HTTP Methods: Sends OPTIONS probe to flag debugging or unsafe methods like TRACE and TRACK.
  • Exposed API Documentation: Probes for unauthenticated disclosure of /openapi.json, /swagger.json, and /api-docs.
3. Controlled Authentication & Authorization Audit app/scanners/auth_audit.py
Implemented

Detects credential leaks, session configuration flaws, and exposed management interfaces:

  • Sensitive File Exposure: Checks for public accessibility of /.env, /.git/HEAD, and /config.json with signature verification.
  • Cookie Flag Auditing: Inspects all Set-Cookie headers to ensure HttpOnly (XSS mitigation), Secure (TLS protection), and SameSite (CSRF defense) are configured.
  • Admin Portal Exposure: Detects public accessibility of administrative login panels (/admin, /administrator).
4. JavaScript Analysis & Secret Harvesting Defense app/scanners/javascript.py
Implemented

Analyzes inline script tags and same-host external JavaScript bundles:

  • Secret & Token Detection: Scans for embedded AWS Access Keys (AKIA...), JSON Web Tokens (eyJ...), and hardcoded API tokens.
  • Dangerous DOM Sinks: Flags use of eval() and document.write() that create DOM-based Cross-Site Scripting vulnerabilities.
  • Vulnerable Client Libraries: Identifies outdated libraries including jQuery < 3.5.0 (CVE-2020-11022), Lodash < 4.17.21, and End-of-Life AngularJS 1.x.
5. Dependency Scanning & Technology Fingerprinting app/scanners/dependencies.py
Implemented

Passive and SBOM manifest auditing:

  • Information Disclosure: Flags granular server version strings in Server and X-Powered-By headers.
  • End-of-Life Server Software: Detects unsupported servers (Apache 2.2, PHP 5.x/7.x).
  • Manifest SBOM Auditing: Audits Python requirements.txt against security advisories for vulnerable packages (e.g. urllib3, requests, Django, Flask).
6. Scheduling & Webhook Notifications app/services/scheduler.py & app/services/notifications.py
Implemented

Continuous automated security operations:

  • Recurring Schedules: Supports hourly, daily, weekly, and monthly recurring scans via /api/schedules.
  • Webhook Dispatcher: Sends formatted alert payloads to configured URLs upon scan completion or when critical/high severity vulnerabilities are detected.

HIGH
Category: api • Risk Score: 7.12 • Confidence: 95% • Fingerprint: c98e1476b8...

The server returns Access-Control-Allow-Origin: * together with Access-Control-Allow-Credentials: true.

Origin requested: https://attacker.example.com; Allow-Origin: *; Allow-Credentials: true
Impact: Malicious cross-origin scripts can execute authenticated actions on behalf of victims.
Remediation: Never combine wildcard origins with credentials. Explicitly whitelist trusted origins.

MEDIUM

HTTP response header 'Content-Security-Policy' was not present.
